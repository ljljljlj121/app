# 云端流式情感识别

原有录制、上传、标注与复核继续使用 9004 服务。新增情感检测独立请求 MER demo 的 9005/v1 接口，不把推理片段上传为待标注样本。

## 板子网页

在原采集 Python 环境运行 `python -m pip install -r requirements-mer.txt`，按原方式启动 collector_v2.py，网页点击“进入云端情感识别”，在独立页面点击“开始检测”。首次保持安静 1.5 秒校准；摄像头和 ROS 麦克风沿用现有配置。停止检测不关闭原采集预览。

切片沿用 MER demo：16kHz 单声道 PCM、20ms WebRTC VAD、200ms 开口确认、300ms 前置缓存、600ms 结束静音、空闲 3 秒和最长 15 秒切片。单个推理线程，只保留 1 段等待任务，新片段替换旧片段并显示替换数量。设备断流会停止并报错。停止会丢弃未提交及排队片段，已发出的请求最多等待 60 秒，其结果不再更新界面。

默认沿用 demo 服务配置。可传 `--mer-api-base`、`--mer-api-key`、`--mer-model`，也支持 OPENAI_BASE_URL / OPENAI_API_KEY 环境变量。9004 数据服务配置保持独立。嵌套 data_collection 目录中的副本也同步了实现。

## 原生安卓（1.0.11）

安卓独立云端页面按“无限等待开口 → 录制语音 → 停顿 600ms 后上传识别 → 显示结果 → 自动返回监听”循环，按停止结束。上传识别期间暂停监听，不并行录制，不创建片段队列。等待时不录制视频，不持续保存音频。每段语音最多 15 秒，不含等待时间。使用 RMS 门槛，手机直接调用推理服务。进入后台会终止循环。板子网页入口仍保留原有持续检测功能。

两个入口均显示已完成片段的情绪和更新时间，不提供模型未返回的置信度。实际摄像头/麦克风及云端服务需实机联调。

本地检查：`python -m unittest discover -s tests -v`；安卓在 android_app 运行 `npx tsc --noEmit`，再按原 README 构建 APK。

上传令牌使用 `--password` 或 `UPLOAD_TOKEN` 环境变量；云端 API Key 使用页面配置、`--mer-api-key` 或 `OPENAI_API_KEY`。源码不内置凭据，首次部署需自行配置。
